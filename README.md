# M4 Launcher

Android 런처 시험 배포 공간입니다. 앱 소스와 서명 키는 포함하지 않습니다.

## 다운로드

[1.4.0-rc132 APK 받기](https://github.com/DANDAN-TT/m4-launcher/releases/tag/v1.4.0-rc132)

설정의 기본 분류 9개는 유지하고 세부 화면을 24개에서 15개로 통합했습니다. 관련 옵션을 한 화면에 모으고 메뉴가 하나인 분류는 바로 엽니다. 상태 정보는 메뉴가 좌우에 있을 때 사이드바 아래에, 하단 메뉴일 때 하단에 표시합니다. 시계·날짜·지역명과 날씨·기온·CPU 온도·사용률을 정리했으며 표시 항목과 CPU 표시 방식·온도 단위는 설정 → 메뉴 → 정보 표시에서 관리합니다.

좌우 버튼 바는 144dp의 같은 크기 두 열로 기능별로 정렬하며, ‘앱’은 큰 버블로 열립니다. 항상 즐겨찾기부터 표시하고 좌우 스와이프로 전체 앱 페이지를 넘깁니다. 상단 탭과 하단 화살표·페이지 표시를 제공하며 길게 누르면 앱 옵션을 엽니다. 별도의 즐겨찾기·최근 앱 버블도 제공합니다.

기본 홈 앱이 아니면 실행 시 설정을 안내합니다. 루트 연결에서는 내비 광고 닫기를 켤 때 M4 Launcher 접근성을 자동으로 준비하며 다른 앱의 접근성을 보존합니다. 개발자 옵션은 설정 열기 버튼 하나로 정리했습니다.

홈 화면에는 선택형 대시보드를 추가했습니다. 설정에서 시계·속도·미디어 중심 배치를 선택하고 이전 배치로 되돌릴 수 있습니다. 앱 표시 크기는 예시와 네 가지 빠른 선택을 제공하며, 기본 선택은 공통 크기를 따릅니다. 즐겨찾기·최근 앱 팝업은 제목·닫기 버튼과 큰 아이콘을 사용하고 높이가 부족하면 스크롤로 모든 행에 접근합니다. 설정의 공통 터치 높이는 최소64dp이며 주간에도 작업 영역 사이 틈과 하단 상태줄은 어둡게 유지합니다.

## 설치와 업데이트

기존 M4 Launcher 배포본은 같은 패키지 `com.totb.m4launcher`와 서명을 유지하므로 APK를 설치해 업데이트할 수 있습니다. 저장한 설정과 앱 선택을 유지합니다.

이전 `com.totb.drivedeck` 앱을 사용한다면 별도 앱으로 설치됩니다. **기존 앱에서 설정 백업 → M4 Launcher 설치 → 설정 복원 → 기본 런처·연결 권한 설정** 순서로 진행하세요.

APK와 업데이트 정보는 GitHub 로그인 없이 받을 수 있습니다. 앱의 **설정 → 관리 → 버전 업데이트 → 시험 버전 받기**를 켠 뒤 같은 화면에서 **새 버전 확인**을 누르세요.

## 엠스틱 관리

**설정 → 기기 → 기기 연결 → 엠스틱 관리(루트)**에서 Mgears 업데이터 비활성화, 부팅 안내창 숨김, 흰색 시스템 버튼 숨김과 CPU 최대 클럭 약 90%·80%·70%·60% 제한을 설정합니다. 변경 확인과 적용 상태 표시, 이전 설정 복구를 제공합니다.

루트 권한이 필요하며 부팅 안내·CPU 유지에는 Magisk가 필요합니다. 검사한 Mstick4 펌웨어 1.9.4·Mstick 앱 2.39.9에서 지원합니다. CPU는 최대 클럭을 제한하며 기기의 과열 보호를 유지합니다. 시스템 버튼은 M4 화면에서만 숨기며 외부 설정·파일 선택창으로 나가거나 런처를 종료하면 다시 표시합니다. 숨기기 옵션을 끄면 이전 제조사 설정을 복원합니다. 업데이터·부팅 안내·CPU의 지속 설정은 앱 삭제만으로 복구되지 않으므로 해제하거나 전체 복구를 먼저 사용하세요.

## 날씨와 접근성

현재 위치 날씨는 사이드바 상태 정보와 설정에 조회한 시·구 등 대략적인 지역명을 표시합니다. 위치 수신 대기·지역 확인 중·지역명 확인 불가를 구분하며, 수동 지역 선택도 지원합니다. 대략적인 위치 권한만 사용하고 약 10km 단위 지역을 Android 지역명 서비스와 Open-Meteo로 보냅니다. 상세 주소·정확한 좌표·이동 기록은 저장하지 않습니다. 기기 센서 온도와 예보 기온은 구분해 표시합니다.

내비 광고 닫기는 접근성으로 지원 내비의 닫기 버튼을 누릅니다. 광고 다운로드 차단 기능은 아닙니다. 루트 자동 준비가 실패하면 Android 접근성 설정으로 안내합니다. 카카오내비·티맵의 지원 팝업은 앱별 토글로 관리합니다. 끄기 확인 뒤에도 등록은 보관하며, 다시 켜면 자동 닫기를 활성화합니다. 추가 닫기 버튼 등록과 등록 해제는 선택 화면에서 관리합니다.

## rc93 이후 변경

홈 시계의 끝 숫자 잘림, 세로 스크롤 중 슬라이더 오입력과 공통 앱 크기 트랙의 짧은 탭 점프를 고쳤습니다. 앱 표시 크기는 ‘작게·맞춤’을 통합하고 낮은 창의 불필요한 스크롤을 줄였으며 큰 글자에서는 균등 격자로 선택합니다. 낮은 버튼 바의 더보기, 업데이트 상태 표시, 하단 정렬과 숨긴 구역의 키 포커스도 개선했습니다. 루트 작업 결과는 해당 작업의 확인된 상태로 표시합니다.

rc130은 내비 광고 자동 닫기를 앱별 토글로 정리했습니다. 카카오내비·티맵의 기본 지원 팝업은 버튼 등록 없이 처리하며, 추가 등록은 선택 메뉴로 분리했습니다. 앱별 OFF는 내장·등록 규칙을 함께 중지하고 기존 등록을 보관합니다. 관찰한 카카오 쿠폰, 티맵 공지·영상 광고만 엄격한 화면 구조로 구분합니다.

rc129의 홈·설정·앱 버블 개선과 Android 권한 화면 터치 보완도 포함합니다. 권한 화면이 가려진 터치로 차단되면 기존 화면을 전체 화면으로 옮기며, 이후 권한은 사용자가 직접 선택합니다. 터치 보안 플래그 제거·자동 권한 승인은 하지 않습니다.

rc132는 DPI 변경 직후와 완전 재실행 후의 화면 차이를 보완했습니다. 공통 크기를 조절한 뒤 **크기 적용**을 누르면 실제 크기가 바뀐 외부 앱 구역만 다시 시작합니다. 앱별 크기 적용도 같은 방식이며 적용 전까지 값과 실행 상태를 유지합니다. 진행 중인 길 안내가 종료될 수 있으므로 적용 전에 안내합니다.

## 검증

- 소유 USB 엠스틱4에서 카카오내비 공통250→300/300→250 DPI와 앱별 크기 적용을 확인했습니다. 공통값은 적용 전까지 저장값·양쪽 앱 프로세스·디스플레이를 바꾸지 않았습니다. 적용 후 카카오내비의 글자 표시를 이전 완전 재실행 캡처와 직접 비교했습니다. 런처 프로세스와 구역 디스플레이를 유지하고 카카오내비만 다시 시작했습니다.
- Java17·SDK34 debug/release 빌드 및 JVM 검사 각각916개 통과, 린트 오류0·경고154, 한영1159쌍을 확인했습니다. Android 회귀 검사2개를 추가하고 기존 슬라이더 검사를 명시적 적용 동작에 맞췄으며 컴파일을 확인했습니다. 이 검사들을 이번 기기에서 instrumentation으로 실행했다고 주장하지 않습니다.
- 배포 APK는 실기기에 설치한 파일과 동일합니다. 6000ms 단언을 완화하지 않았으며 카카오내비 전체 시작 시간을6000ms 이내로 보장하는 수정은 아닙니다.

## 알려진 문제

- 이번 DPI 적용 검사 중 종료되던 카카오내비 프로세스에서 네이티브 오류(SIGSEGV)1회를 추가로 관찰했습니다. 새 프로세스는 정상 화면으로 돌아왔지만 해당 오류의 원인과 해결은 미확정입니다. 이전 카카오내비→티맵 전환 중 네이티브 종료1회, 내비 확대 잔상2건, 외부 화면 복귀 시 구역 앱 재로딩도 미해결입니다.
- 강제 종료 등으로 접근성이 꺼지면 광고 닫기 설정에서 다시 켜야 합니다. 사용자 티맵 미작동, 네이버지도 실제 광고 및 모든 광고 변형은 검증 완료로 간주하지 않습니다.
- 실제 주행·DRM·장시간 발열 절감과84개 기능 목록의 계획·부분 항목은 이번 검증 범위에 포함하지 않습니다.

## 업데이트

설정 → 관리 → 버전 업데이트 → ‘시험 버전 받기’를 켠 뒤 ‘새 버전 확인’을 누르세요. 기존 개인 배포본은 삭제하지 않고 업데이트합니다.
